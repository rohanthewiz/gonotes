## Scope decision

No session doc recorded a use case for per-note compaction. Two findings
framed the question:

- Whole-log compaction already rewrites per entity (`compactNoteGroup`), so a
  per-note pass does a subset of the same work.
- Nothing in the app reads `note_changes` as user-visible history. The only
  readers are sync, compaction and the conflict code. So pending change rows
  are invisible, and compacting the whole log takes nothing from a user that
  a per-note pass would keep.

The user was offered three options: decline (recommended), backend only, or
backend plus web and TUI buttons. **They chose backend only.** No UI was
built, and no follow-up item was raised for one.

## Design

```
pending log                         CompactNotePendingChanges(peer, user, A)
  A: create ─ update ─ update   ──►   A: create (snapshot of A now)
  B: update ─ update            ──►   B: update ─ update     (untouched)
  cat X: update ─ update        ──►   cat X: update ─ update (untouched)
```

### `models/sync_compact_note.go` (new)

- `CompactNotePendingChanges(peerID, userGUID, noteGUID)` and
  `PreviewNoteCompaction(...)`. Counts are **that note's** pending changes:
  `ChangesBefore` is how many it had, `ChangesAfter` is 1 when compacted, and
  `NotesCompacted` is 0 or 1. The real pass re-reads the group afterwards
  rather than assuming 1, because `compactNoteGroup` logs and carries on if
  deleting a superseded row fails.
- `pendingNoteGroup` loads the peer's whole pending log with
  `GetUnsentChangesForPeer(peerID, "", 0)`, keeps the note's rows, and runs
  them through `groupNoteChanges`, which drops `OperationSync` rows and
  sorts. Two reasons it doesn't query by `note_guid`:
  - The selection and ordering rules stay identical to the whole-log pass.
  - The user-filtered form joins each database to *its own* `notes` table.
    After a privacy flip, that join drops the changes left in the note's
    former database.
- `checkNoteOwner` looks up `SELECT created_by FROM notes WHERE guid = ?` in
  both databases via `firstFromBothNotes`, **including soft-deleted rows**. A
  tail ending in a delete is the best case for compaction, and
  `GetNoteByGUID` hides deleted notes. With a non-empty `userGUID`, a
  different owner is refused.
- `ErrCompactNoteNotFound` covers both unknown and foreign notes, so the
  answer can't be used to probe for other users' GUIDs.
- `noteGroupCompactable` is the single decline rule: fewer than two changes,
  or a non-delete net result for a note that is gone. `PreviewCompaction`'s
  note loop now calls it too, so the two previews can't drift.
  `TestPreviewCompactionMatchesTheRealPass` still passes.

Category ordering is safe without touching categories. The replacement keeps
the `created_at` of the last change it swallows, so it sits at or after every
position the note's changes held. Any category definition that preceded them
still precedes it.

### Wiring

- `SyncClient.CompactNote(noteGUID, userGUID)` and `PreviewCompactNote`. They
  take `userGUID`, unlike `Compact()`, because they name a note and a spoke
  can have several local accounts.
- `web/api/sync_control.go`: `SyncControlCompact` (POST) and
  `SyncControlCompactPreview` (GET) read
  `ctx.Request().QueryParam("note_guid")`. `ErrCompactNoteNotFound` maps to
  404. With no parameter, both behave as before.
- `models.ResetSyncClientForTest()`, next to `GetSyncClient`.
  `NewSyncClient` installs itself globally, and a leftover client would make
  later tests' servers spokes.
- Docs: a `?note_guid=` row in `README.md`'s sync-control table and in
  `.claude/skills/gonotes/SKILL.md`.
